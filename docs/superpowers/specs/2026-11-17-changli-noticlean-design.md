# 长理通知降噪与智能解析助手设计文档

- 日期：2026-11-17
- 状态：已获用户确认
- 应用形态：Python Streamlit 轻量级 Web 应用

## 1. 背景与目标

长沙理工大学学生需要从微信群、QQ 群转发内容中快速识别重要通知。应用接收粘贴文本或可选 OCR 识别后的截图文本，过滤闲聊噪音，输出统一的通知解析卡片，突出截止时间、面向对象、地点和下一步行动。

首版目标：

1. 默认完全本地运行，无需 API Key。
2. 支持一条或多条通知的结构化解析与倒计时。
3. 信息不足时明确提示待确认，不编造字段。
4. 支持可选本地 OCR 和可选 OpenAI 兼容大模型增强。
5. 支持 Markdown、JSON 导出，不持久化通知内容。

## 2. 范围

### 2.1 首版包含

- 通知文本粘贴、示例填充、文本文件上传。
- PNG/JPG/JPEG 截图上传及可选 Tesseract 中文 OCR。
- 噪音清理、校园通知相关性判断、安全风险检测。
- 多通知拆分与五要素提取。
- 常见中文日期表达解析、相对倒计时及紧急程度标记。
- 严格的 Markdown 通知卡片和一句防踩坑提示。
- 可选大模型增强、失败回退、Markdown/JSON 下载。
- 解析模块自动化测试和 Streamlit 页面冒烟验证。

### 2.2 首版不包含

- 用户账号、数据库、历史记录和云同步。
- 微信群或 QQ 群自动抓取。
- 独立 FastAPI 服务和前后端分离部署。
- 对任意自然语言通知的百分之百准确理解。
- 内置或硬编码任何第三方模型 API 地址、密钥。

## 3. 技术方案

采用模块化单体结构：Streamlit 只负责交互和展示，解析逻辑放在独立 Python 包中。核心依赖仅包含 Streamlit；OCR 依赖单独声明，大模型请求使用 Python 标准库，避免强制引入 SDK。

建议结构：

```text
app.py
noticlean/
  __init__.py
  models.py
  parser.py
  dates.py
  llm.py
  ocr.py
  render.py
requirements.txt
requirements-ocr.txt
requirements-dev.txt
tests/
```

模块职责：

- `models.py`：结构化数据模型及序列化。
- `dates.py`：中文时间识别、年份推定、倒计时和紧急程度。
- `parser.py`：降噪、拆分、相关性、风险和五要素提取。
- `llm.py`：可选大模型请求、JSON 校验和结果转换。
- `ocr.py`：可选依赖检测和截图文字识别。
- `render.py`：通知卡片及导出文本生成。
- `app.py`：输入、侧边栏配置、解析触发、异常提示及结果展示。

## 4. 页面与交互

页面标题为“长理通知降噪助手”，采用校园蓝和暖橙提醒色，保持移动端可读性。

主区域：

1. “粘贴通知”和“上传截图”输入方式。
2. 文本输入支持直接粘贴及 `.txt` 文件；截图输入展示上传图片并提供 OCR 按钮。
3. 提供示例填充和清空操作。
4. 点击“一键提炼重点”后显示本地解析结果。
5. 结果区域展示安全提示、通知卡片及 Markdown/JSON 下载按钮。

侧边栏：

- 参考时间默认取系统当前时间，可手动修改。
- 大模型增强默认关闭。
- 开启后显示接口地址、模型名称、API Key 密码输入框。
- 显示隐私说明：配置仅用于当次请求，通知内容不保存。

## 5. 本地解析流水线

### 5.1 降噪

删除独立的“收到”“谢谢”“感谢”“顶顶顶”“dd”“+1”等回应行、纯表情行、重复转发标记和连续空行。保留包含日期、地点、链接、对象或行动要求的正文，避免误删有效信息。

### 5.2 相关性判断

结合校园场景词和通知行为词判断输入是否为校园通知。明显无关的闲聊、段子或纯代码输入不生成卡片，而显示角色约定的引导语。无法确定但存在通知要素时仍可解析，并提示核对来源。

### 5.3 风险检测

检测缴费、转账、押金、银行卡、验证码、非官方短链或可疑链接等信号。命中后在结果顶部显示：

> 安全提示：检测到该通知可能涉及非官方收费或敏感链接，请务必通过学校官网或官方渠道二次核实，谨防受骗！

风险检测不替代人工判断，也不将正常学校收费通知直接认定为诈骗。

### 5.4 多通知拆分

优先依据显式卡片分隔线、编号标题、连续“通知主题 + 截止时间”等强边界拆分。边界不明确时保留为一条，避免把同一通知的对象、地点和行动说明拆散。每条通知独立提取字段和倒计时。

### 5.5 五要素提取

- 事件名称：优先提取通知标题、主题或首条有效概括句。
- 截止时间：优先识别“截止、截至、之前、前完成、逾期”等语境附近时间。
- 面向对象：识别年级、专业、学院、学生类别及“全校同学”等表达。
- 地点/平台：识别云塘、金盆岭、楼栋教室及线上平台、链接。
- 核心行动：保留报名、组队、提交、缴费警告、材料要求、群号和链接等下一步动作。

字段无法可靠识别时显示“未在通知中找到明确……，建议二次确认”，不根据常识补齐。

## 6. 时间规则

支持：

- `YYYY年M月D日 HH:mm`、`YYYY-MM-DD HH:mm` 及常见中文变体。
- 无年份日期，年份取参考时间所在年份并标记为推定。
- `今天、明天、后天、大后天`。
- `本周/下周 + 星期` 等常见表达。
- `上午、中午、下午、晚上` 等时段修正。

只提供日期时，以当天 `23:59` 计算参考倒计时，并在卡片明确写出“具体时刻未注明，倒计时按当日 23:59 估算”。完全无法识别时显示约定中的缺失提示，不计算倒计时。

紧急程度：

- 已过期：显示“已截止，请确认是否仍可补交”。
- 不足或等于 24 小时：紧急。
- 大于 24 小时且不足或等于 72 小时：抓紧。
- 大于 72 小时：时间充裕。

倒计时按完整天和剩余小时展示；不足一小时显示为 0 小时，不四舍五入延长剩余时间。

## 7. 可选 OCR

OCR 使用 `pytesseract`、Pillow 和系统 Tesseract 中文语言包。未安装可选依赖、找不到可执行程序或缺少中文语言数据时，页面给出安装提示并允许用户改为粘贴文本，不导致应用崩溃。OCR 结果进入可编辑文本框，经用户确认后再解析。

## 8. 可选大模型增强

默认仅使用本地解析。用户主动开启后，应用将当前通知文本和本地解析结果发送到用户配置的 OpenAI 兼容 Chat Completions 接口，要求模型返回固定 JSON 结构。

约束：

- API Key 使用密码输入，仅保存在当前 Streamlit 会话组件状态中，不写文件、不打印。
- 请求设置有限超时，异常时保留本地结果并显示简短警告。
- 只接受合法 JSON 和规定字段，忽略未知字段。
- 模型结果用于补充或修正文本字段；本地代码重新计算倒计时、紧急程度和安全警告。
- 模型不得把缺失时间转换为看似精确的虚构时间；无法确认时保持空值。

## 9. 数据模型与输出

每条通知包含：事件名称、原始时间文本、可选结构化截止时间、时间是否估算、倒计时文本、紧急程度、面向对象、地点或平台、核心行动列表、提取链接和贴心提示。

整体结果包含：输入是否相关、通知列表、全局安全警告和可选运行警告。JSON 导出使用 UTF-8 中文，Markdown 导出沿用角色约定的卡片格式，多条通知用 `---` 分隔。

## 10. 异常与边界处理

- 空输入：提示先粘贴通知或上传截图。
- 无关输入：显示规定引导语，不生成虚假卡片。
- 信息缺失：保留可提取字段，其余明确待确认。
- 多条混合：仅在强边界存在时拆分，逐条展示。
- OCR 不可用：说明缺失组件并保留文本入口。
- 大模型失败：回退本地结果，不阻断页面。
- 风险内容：显示安全警告，仍允许用户查看已提取的原始事实。

## 11. 验证与验收

验证覆盖核心解析、时间边界、多通知拆分、无关输入、风险提示、可选能力失败回退、导出格式和页面主要交互。解析模块测试不依赖外部模型或真实 OCR 服务；网络与大模型行为使用本地替身。

验收标准：

1. 安装核心依赖后可启动应用，粘贴通知即可获得卡片。
2. 无 OCR、无 API Key 时核心功能仍可用。
3. 示例通知的五要素、倒计时、紧急程度和提示符合规则。
4. 多通知、信息缺失、无关文本和风险文本均按约定处理。
5. 大模型异常不会产生未处理异常或覆盖本地安全计算。
6. 自动化测试通过，Streamlit 页面能够完成主要输入到结果展示的流程。
